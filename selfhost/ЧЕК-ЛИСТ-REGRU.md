# Переезд кабинета на Reg.ru — пошаговый чек-лист

Инструкция для человека без опыта. Выполняйте шаги строго по порядку,
не пропуская. Каждая команда — это одна строка, которую нужно скопировать
и вставить в чёрное окно (терминал), затем нажать Enter.

Всего примерно 1,5 часа. Домен остаётся у вашего текущего регистратора,
на Reg.ru берём только сервер.

**Обозначения в тексте:**

- `fixkey.ru` — везде заменяйте на свой настоящий домен
- `ЧИСЛО.ЧИСЛО.ЧИСЛО.ЧИСЛО` — IP-адрес сервера, вы получите его на шаге 1

---

## Шаг 0. Что подготовить заранее

> **Если кабинет сейчас не открывается** и вместо данных ошибка —
> это исчерпан лимит платформы. Данные при этом целы, база работает.
> Раздел «Переезд» внутри кабинета в таком состоянии тоже не откроется,
> поэтому значения берём напрямую из панели, как описано ниже.

Откройте блокнот и выпишите туда данные — они понадобятся.

1. Откройте раздел **Ядро → Секреты** в poehali.dev
2. Значения там скрыты, но их можно скопировать: наведите на строку
   секрета и нажмите на иконку копирования (или откройте секрет
   на редактирование — значение подставится в поле)
3. Выпишите в блокнот:
   - `AWS_SECRET_ACCESS_KEY` — **самое важное**, без него сотрудники
     не смогут войти по своим паролям
   - `DATABASE_URL` — адрес текущей базы, для переноса данных
   - `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` — для писем о заявках

Также придумайте и запишите **пароль для новой базы данных** —
любые 16 символов латиницей и цифрами, без пробелов.

> Держите блокнот с этими данными в надёжном месте, никому не пересылайте.

**Если значение `AWS_SECRET_ACCESS_KEY` скопировать не удаётся** —
не страшно, переезд всё равно возможен. В этом случае на шаге 5
впишите в `PASSWORD_SALT` любое значение, например `fixkey_salt_new`,
а на шаге 12 задайте себе новый пароль одной командой — она приведена там.

## Шаг 1. Заказать сервер на Reg.ru

1. Зайдите на **reg.ru** → войдите в личный кабинет
2. Сверху меню **Услуги** → **Облачные серверы (VPS)**
3. Нажмите **Заказать сервер**
4. Выбирайте так:
   - Тариф: **Cloud-2** (2 ядра, 4 ГБ памяти, 40 ГБ диска)
   - Операционная система: **Ubuntu 24.04**
   - Дата-центр: **Москва**
   - Резервные копии: **включить** (стоит недорого, но спасает)
5. Оплатите заказ

Через 5–10 минут на почту придёт письмо с данными сервера.
Выпишите в блокнот:

- **IP-адрес** — четыре числа через точку
- **Пароль пользователя root**

## Шаг 2. Подключиться к серверу

**Если у вас Windows:** нажмите «Пуск», напечатайте `PowerShell`, откройте его.
**Если у вас Mac:** нажмите Cmd+Пробел, напечатайте `Терминал`, откройте.

Откроется чёрное (или синее) окно. Вставьте туда команду, подставив свой IP:

```
ssh root@ЧИСЛО.ЧИСЛО.ЧИСЛО.ЧИСЛО
```

Спросит `Are you sure you want to continue connecting?` — напечатайте `yes` и Enter.

Затем спросит пароль. Вставьте пароль root из письма.

> **Важно:** при вводе пароля на экране ничего не появляется — ни точек,
> ни звёздочек. Это нормально, просто вставьте и нажмите Enter.

Получилось, если строка стала выглядеть так: `root@vps:~#`

## Шаг 3. Установить нужные программы

Скопируйте и выполните команды по одной, дожидаясь окончания каждой.

Обновляем сервер (займёт 2–3 минуты):

```
apt update && apt upgrade -y
```

Ставим Docker, веб-сервер и вспомогательные программы:

```
apt install -y docker.io docker-compose-v2 nginx certbot python3-certbot-nginx git postgresql-client
```

Отдельно ставим Node 20 — версия из стандартного набора Ubuntu
слишком старая, на ней сборка сайта не пройдёт:

```
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs
```

Включаем Docker:

```
systemctl enable --now docker
```

Проверяем, что всё встало:

```
docker --version && nginx -v && node --version
```

Должны увидеть три строки с версиями. У Node должно быть **v20** или выше —
если там v18, повторите команду установки Node выше.

## Шаг 4. Загрузить код кабинета на сервер

Сначала выгрузите код из платформы в GitHub:

1. В poehali.dev нажмите **Скачать** → **Подключить GitHub**
2. Авторизуйтесь, выберите аккаунт, дождитесь загрузки
3. Скопируйте адрес получившегося репозитория — вида
   `https://github.com/vicershow-ux/moonlight-initiative-47.git`

### Куда вводить токен

Отдельно «добавлять» токен никуда не нужно — он вставляется прямо
в команду скачивания кода, один раз. В команде ниже замените только
`ВАШ_ТОКЕН` на свой токен, остальное уже подставлено:

```
mkdir -p /var/www && cd /var/www && git clone https://vicershow-ux:ВАШ_ТОКЕН@github.com/vicershow-ux/moonlight-initiative-47.git fixkey
```

Удобнее собрать эту строку в блокноте на своём компьютере, а потом
целиком вставить в чёрное окно: правая кнопка мыши или **Ctrl+Shift+V**.

Пойдут строки `Receiving objects...` — значит доступ принят,
код скачивается. Это занимает меньше минуты.

> **Если написало `destination path ... already exists`** — код уже
> скачан ранее, токен принят, всё в порядке. Просто переходите
> к следующему разделу.

### Обязательно: убрать токен с сервера

После успешной загрузки токен не должен оставаться на сервере открытым.
Первая команда убирает его из настроек папки:

```
cd /var/www/fixkey && git remote set-url origin https://github.com/vicershow-ux/moonlight-initiative-47.git
```

Вторая стирает его из истории набранных команд:

```
history -c && rm -f ~/.bash_history
```

### Если написало `Authentication failed`

Чаще всего одна из трёх причин:

- в адресе указали почту вместо логина GitHub
- при создании токена не отметили галочку **repo** — проверьте
  в настройках токена на GitHub, при необходимости создайте новый
- токен скопирован не полностью

Исправьте и повторите команду, добавив в начало удаление неудачной папки:

```
rm -rf /var/www/fixkey && mkdir -p /var/www && cd /var/www && git clone https://vicershow-ux:ВАШ_ТОКЕН@github.com/vicershow-ux/moonlight-initiative-47.git fixkey
```

Проверяем, что код на месте:

```
ls /var/www/fixkey/selfhost
```

Должен появиться список файлов: `Dockerfile`, `README.md`, `server.py` и другие.

## Шаг 5. Заполнить настройки

Файл настроек **не нужно создавать с нуля** — в коде уже лежит заготовка
`.env.example` со всеми строками и пояснениями. Мы делаем с неё рабочую
копию с именем `.env` и правим значения:

```
cd /var/www/fixkey/selfhost && cp .env.example .env && nano .env
```

### Где этот редактор и как в него попасть

**Никуда переходить не нужно.** Редактор открывается сам, прямо
в том же чёрном окне, где вы работаете с шага 2. Последнее слово
в команде — `nano` — это и есть команда «открой редактор».

После нажатия Enter окно изменится: вместо строки `root@vps:~#`
весь экран заполнится текстом настроек, а внизу появится полоска
с подсказками вида `^O Записать` и `^X Выход`. Значит, вы уже внутри
редактора — это и есть нужное окно.

### Как в нём работать

Мышь здесь не работает — только клавиатура:

- перемещение по тексту — **стрелки** на клавиатуре
- поставить курсор в нужное место, где хотите вписать значение,
  и печатать как обычно
- удалить лишнее — **Backspace**

Подставляйте свои значения сразу после знака `=`, без пробелов
и без кавычек. Строки, которые начинаются с `#`, — это подсказки
для вас, их менять не нужно.

> Значок `^` в подсказках внизу означает клавишу **Ctrl**.
> То есть `^O` — это Ctrl и латинская буква O, нажатые вместе.

Что заполнить обязательно — всего три строки:

```
DB_PASSWORD=пароль_который_вы_придумали
CORS_ORIGIN=https://fixkey.ru
PASSWORD_SALT=значение_AWS_SECRET_ACCESS_KEY_из_блокнота
```

> Строку `DATABASE_URL` при запуске через Docker менять не нужно —
> адрес базы соберётся сам из `DB_PASSWORD`. Оставьте её как есть.

Почта для заявок (если переносите):

```
SMTP_HOST=значение_из_блокнота
SMTP_USER=значение_из_блокнота
SMTP_PASSWORD=значение_из_блокнота
```

Остальные строки — `HOST`, `PORT` и блок хранилища файлов — оставьте
как есть, их настроим позже при необходимости.

### Как сохранить и выйти

Три нажатия по порядку:

1. **Ctrl+O** — внизу появится строка `Имя файла для записи: .env`
2. **Enter** — подтверждаете имя, появится `[ Записано строк: 36 ]`
3. **Ctrl+X** — редактор закроется, вернётся строка `root@vps:~#`

Если снова видите `root@vps:~#` — вы вышли, всё сохранено.

> **Если запутались и хотите начать заново:** нажмите **Ctrl+X**,
> затем на вопрос о сохранении нажмите **N** (не сохранять).
> После этого повторите команду `cp .env.example .env && nano .env`
> из начала шага — файл вернётся к исходному виду.

> Если `PASSWORD_SALT` достать не удалось — впишите туда любое значение,
> например `fixkey_salt_new`. Тогда на шаге 12 вы зададите себе новый
> пароль одной командой и спокойно войдёте.

### Если с редактором не сложилось

Можно обойтись совсем без него. Замените в командах ниже значения
на свои и выполните их по очереди — файл заполнится сам:

```
cd /var/www/fixkey/selfhost && cp .env.example .env
```

```
sed -i 's|^DB_PASSWORD=.*|DB_PASSWORD=ВашПарольБазы|' .env
```

```
sed -i 's|^CORS_ORIGIN=.*|CORS_ORIGIN=https://fixkey.ru|' .env
```

```
sed -i 's|^PASSWORD_SALT=.*|PASSWORD_SALT=ЗначениеИзБлокнота|' .env
```

Почта для заявок (если переносите):

```
sed -i 's|^SMTP_HOST=.*|SMTP_HOST=значение|; s|^SMTP_USER=.*|SMTP_USER=значение|; s|^SMTP_PASSWORD=.*|SMTP_PASSWORD=значение|' .env
```

Проверяем, что всё записалось:

```
grep -E "^(DB_PASSWORD|CORS_ORIGIN|PASSWORD_SALT|SMTP_HOST)=" .env
```

Должны увидеть четыре строки со своими значениями. Слова
«ПРИДУМАЙТЕ_ПАРОЛЬ» остаться не должно.

Проверяем, что файл создан:

```
ls -l /var/www/fixkey/selfhost/.env
```

Закрываем файл от посторонних:

```
chmod 600 /var/www/fixkey/selfhost/.env
```

## Шаг 6. Запустить сервер кабинета

```
cd /var/www/fixkey/selfhost && docker compose up -d --build
```

Первый запуск идёт 3–5 минут — скачиваются компоненты. Ждите.

Проверяем:

```
curl http://localhost:8000/health
```

Должны увидеть ответ со словом `"ok"` и списком из 16 разделов.

> На этом шаге сервер создаст пустые таблицы — это нормально.
> На следующем шаге они заменятся вашими настоящими данными.

Если ответа нет — смотрите, что пошло не так:

```
docker compose logs --tail 30 api
```

## Шаг 7. Перенести данные из платформы

> Выгрузка базы работает, даже если кабинет не открывается из-за лимита —
> ограничение касается только функций, а не самой базы.

Адрес старой базы вам знать не нужно — выгрузка уже подготовлена
и лежит по ссылке. Достаточно скачать её на сервер.

### Скачиваем выгрузку

```
curl -L "https://cdn.poehali.dev/projects/17c1a9d3-9c72-4270-abec-e542b49c03f2/bucket/export/fixkey-20260905-124939.sql.gz" -o /root/fixkey.sql.gz
```

Проверяем, что файл на месте:

```
ls -lh /root/fixkey.sql.gz
```

Размер должен быть около `93K`. Если `0` или файла нет — повторите
команду скачивания.

Распаковываем:

```
gunzip -f /root/fixkey.sql.gz && ls -lh /root/fixkey.sql
```

Теперь размер около `1,1M` — это ваши данные в виде текста.

### Загружаем данные в новую базу

Таблицы уже созданы на шаге 6, поэтому просто заливаем содержимое:

```
cd /var/www/fixkey/selfhost && docker compose cp /root/fixkey.sql db:/tmp/fixkey.sql
```

```
docker compose exec -T db psql -U fixkey -d fixkey -f /tmp/fixkey.sql > /root/load.log 2>&1; tail -3 /root/load.log
```

Загрузка занимает около минуты. Строки со словом `NOTICE` — это
нормально, на них внимания не обращайте.

### Проверяем, что всё перенеслось

```
docker compose exec -T db psql -U fixkey -d fixkey -c "SELECT (SELECT COUNT(*) FROM users) AS сотрудники, (SELECT COUNT(*) FROM objects) AS объекты, (SELECT COUNT(*) FROM services) AS услуги, (SELECT COUNT(*) FROM warehouse_items) AS склад;"
```

Должно показать ровно эти числа:

| сотрудники | объекты | услуги | склад |
|---|---|---|---|
| 4 | 5 | 2002 | 150 |

Если числа совпали — данные переехали полностью.

> **Если увидели ошибки `relation does not exist`** — значит таблицы
> ещё не создались на шаге 6. Выполните `docker compose exec -T api
> python3 migrate.py` и повторите загрузку.

Отмечаем базу как актуальную, чтобы сервер не пытался пересоздать таблицы:

```
docker compose exec -T api python3 migrate.py --mark-applied
```

Перезапускаем сервер:

```
docker compose restart api && sleep 5 && curl -s http://localhost:8000/health
```

## Шаг 8. Собрать сайт

Указываем сайту адрес нового сервера — **замените `fixkey.ru` на свой**:

```
cd /var/www/fixkey && printf 'VITE_API_BASE=https://api.fixkey.ru\nVITE_SITE_URL=https://fixkey.ru\n' > .env.production
```

Проверяем, что записалось верно:

```
cat /var/www/fixkey/.env.production
```

Должны увидеть ровно две строки: `VITE_API_BASE=https://api.fixkey.ru`
и `VITE_SITE_URL=https://fixkey.ru`.

Собираем (займёт 3–5 минут):

```
cd /var/www/fixkey && npm install && npm run build
```

В конце сборки появятся строки `[sitemap]` и `[prerender]`. Если рядом
с ними написано `не удалось получить услуги` — ничего страшного,
сайт соберётся, а карта услуг обновится позже сама.

Проверяем, что сайт собрался:

```
ls /var/www/fixkey/dist/index.html
```

Должен показать путь к файлу.

Проверяем, что сайт будет обращаться к вашему серверу:

```
grep -rlo "api.fixkey.ru" /var/www/fixkey/dist/assets/ | head -1
```

Должен вывестись путь к файлу — значит адрес вашего сервера попал в сборку.
Если пусто — проверьте файл `.env.production` и соберите заново.

> В файлах сборки останутся и старые адреса платформы — это запасной
> список, который не используется, когда задан `VITE_API_BASE`.
> Беспокоиться из-за них не нужно.

## Шаг 9. Настроить веб-сервер

Создаём настройку:

```
nano /etc/nginx/sites-available/fixkey
```

Вставьте текст ниже целиком, **заменив `fixkey.ru` на свой домен**
(в редакторе вставка — правая кнопка мыши или Ctrl+Shift+V):

```
server {
    listen 80;
    server_name fixkey.ru www.fixkey.ru;
    root /var/www/fixkey/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}

server {
    listen 80;
    server_name api.fixkey.ru;

    client_max_body_size 20M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

Сохраните: **Ctrl+O**, **Enter**, **Ctrl+X**.

Включаем настройку:

```
ln -sf /etc/nginx/sites-available/fixkey /etc/nginx/sites-enabled/ && rm -f /etc/nginx/sites-enabled/default && nginx -t
```

Должна появиться надпись `syntax is ok` и `test is successful`.

```
systemctl reload nginx
```

## Шаг 10. Направить домен на сервер

Зайдите в панель управления **вашего текущего регистратора** домена
(там, где куплен домен) и найдите раздел **DNS-записи** или
**Управление зоной**.

Создайте три записи, подставив IP вашего сервера:

| Тип | Имя (поддомен) | Значение |
|-----|----------------|----------|
| A | `@` | ЧИСЛО.ЧИСЛО.ЧИСЛО.ЧИСЛО |
| A | `www` | ЧИСЛО.ЧИСЛО.ЧИСЛО.ЧИСЛО |
| A | `api` | ЧИСЛО.ЧИСЛО.ЧИСЛО.ЧИСЛО |

Сохраните. Обновление адресов занимает от 15 минут до 3 часов.

Проверить, готово ли (выполняйте на сервере):

```
ping -c 2 api.fixkey.ru
```

Если в ответе виден IP вашего сервера — можно продолжать.
Если нет — подождите и повторите.

## Шаг 11. Включить защищённое соединение

Только после того, как шаг 10 заработал:

```
certbot --nginx -d fixkey.ru -d www.fixkey.ru -d api.fixkey.ru
```

Программа спросит:

- **почту** — впишите свою, туда придут напоминания о продлении
- **согласие с условиями** — напечатайте `Y`
- **рассылку** — можно `N`
- **перенаправление на https** — выберите вариант `2` (перенаправлять)

Сертификат бесплатный и продлевается автоматически.

## Шаг 12. Проверить, что всё работает

Откройте в браузере `https://fixkey.ru` — должен открыться сайт с замочком.

Затем `https://fixkey.ru/login` и входите:

- **если вы перенесли `PASSWORD_SALT`** со старой платформы — своим
  обычным логином и паролем, они продолжают работать;
- **если ключ достать не удалось** — сначала задайте себе новый пароль
  командой из раздела ниже, затем входите с ним.

Пройдите по разделам и убедитесь, что данные на месте:

- Объекты
- Сметы
- Склад
- Аренда
- Договоры и акты

**Если войти не удаётся** — почти наверняка неверно указан `PASSWORD_SALT`.
Проверьте, что вписали туда значение `AWS_SECRET_ACCESS_KEY` со старой платформы:

```
cd /var/www/fixkey/selfhost && nano .env
```

После исправления перезапустите:

```
docker compose restart api
```

### Если старый ключ достать не удалось

Тогда войти по прежним паролям нельзя, но доступ возвращается одной командой.

Задайте себе новый пароль — подставьте свою почту и придуманный пароль:

```
cd /var/www/fixkey/selfhost && docker compose exec -T api python3 set-password.py randerr@yandex.ru ПридумайтеНовыйПароль
```

Должно вывести `Пароль обновлён: Ершов Виктор Витальевич (owner)`.
Теперь входите на сайте с этой почтой и новым паролем.

Если ошиблись в почте — скрипт покажет список всех учётных записей,
которые есть в базе. Выберите нужную и повторите команду.

Пароли сотрудникам после входа задайте в разделе **Команда**.

## Шаг 13. Настроить резервные копии

Чтобы данные не пропали, настроим ежедневную копию базы.

```
mkdir -p /backup && crontab -e
```

Если спросит про редактор — выберите `1` (nano).

В конец файла добавьте одной строкой:

```
0 3 * * * cd /var/www/fixkey/selfhost && docker compose exec -T db pg_dump -U fixkey fixkey | gzip > /backup/fixkey-$(date +\%F).sql.gz && find /backup -name "*.sql.gz" -mtime +30 -delete
```

Сохраните: **Ctrl+O**, **Enter**, **Ctrl+X**.

Теперь каждую ночь в 3 часа будет создаваться копия, а копии старше
30 дней — удаляться. Проверить копию вручную можно так:

```
cd /var/www/fixkey/selfhost && docker compose exec -T db pg_dump -U fixkey fixkey | gzip > /backup/проверка.sql.gz && ls -lh /backup
```

## Шаг 14. Закрыть лишние двери

Оставим открытыми только нужные порты:

```
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
```

Проверка:

```
ufw status
```

Кабинет работает на вашем сервере. Лимитов на количество обращений больше нет —

# Как обслуживать дальше

**Посмотреть, что происходит на сервере:**

```
cd /var/www/fixkey/selfhost && docker compose logs --tail 50 api
```

**Перезапустить кабинет, если подвис:**

```
cd /var/www/fixkey/selfhost && docker compose restart
```

```
cd /var/www/fixkey && git pull && npm run build && cd selfhost && docker compose up -d --build
```

**Восстановить данные из копии (если что-то случилось):**

```
cd /var/www/fixkey/selfhost && gunzip -c /backup/fixkey-ДАТА.sql.gz | docker compose exec -T db psql -U fixkey -d fixkey
```

# Если что-то пошло не так

**Сайт не открывается, браузер пишет «не удаётся найти сайт»**
Домен ещё не направился на сервер. Подождите и проверьте шаг 10.

**Сайт открылся, но пустой или без данных**
Проверьте сервер: `curl http://localhost:8000/health`.
Если ответа нет — `docker compose logs --tail 30 api`.

**Браузер ругается на доступ, данные не грузятся**
В файле `.env` в строке `CORS_ORIGIN` должен быть ваш домен с `https://`
и без косой черты в конце. После правки: `docker compose restart api`.

**Не входит по паролю**
Неверный `PASSWORD_SALT`. См. шаг 12.

**Не загружаются фото**
Файлы пока берутся из хранилища платформы. Для полной независимости
подключите своё S3-хранилище — как, описано в файле `README.md`.

**Забыли пароль от сервера**
В личном кабинете Reg.ru у сервера есть кнопка сброса пароля root.
